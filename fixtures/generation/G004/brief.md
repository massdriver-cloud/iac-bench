# Request: a standard Aurora PostgreSQL module for production databases

Our platform team provisions the PostgreSQL databases behind our customer-facing services, and we're moving the ones that matter most onto Aurora. Today each of those databases lives in a single region, and the last regional outage took checkout down for most of an afternoon. Build the reusable OpenTofu module the platform team will use to stand up these production databases from now on. The business has set the bar: if an AWS region fails, a service's database must be serving again from another region within minutes, having lost no more than a few seconds of writes. Our services run on EKS in two US AWS regions and reach AWS through IAM roles; in each region the network team owns one VPC per environment (`apps-staging` and `apps-prod`) and has already created private database subnets in each, tagged `tier = database`. These databases hold customer and payment data, and the security team audits who accesses them and how. The platform engineers know AWS well but aren't database specialists: they'll fill in what's specific to each service and trust the module for the rest. You own every design decision the module makes.
